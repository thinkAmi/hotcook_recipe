## Purpose
レシピ群から生成される検索用の構造化データ（検索インデックス）の内容と保証を定める。ブラウザ側の検索・表示はこのデータだけを前提にし、レシピの Markdown を直接読まない。データ化と検索の層分離を守るための契約。
## Requirements
### Requirement: 全レシピを1つの JSON に集約する
ビルドは、レシピ置き場のすべての Markdown ファイルを読み、公開ディレクトリ配下に検索インデックスを1つの JSON ファイルとして出力しなければならない（SHALL）。JSON はレシピオブジェクトの配列である。

#### Scenario: 複数レシピをビルドする
- **WHEN** レシピ置き場に3件のレシピがある
- **THEN** 出力 JSON は要素数3の配列になる

#### Scenario: レシピが1件も無い
- **WHEN** レシピ置き場に Markdown ファイルが1つも無い
- **THEN** ビルドは失敗し、レシピが無い旨を報告する

#### Scenario: いずれかのレシピに不備がある
- **WHEN** 1件でも frontmatter の必須項目欠落や YAML 破損があるレシピが含まれる
- **THEN** ビルドは失敗し、インデックスを出力しない（不完全なインデックスで上書きしない）

### Requirement: レシピオブジェクトの形
各レシピは次のキーを持つオブジェクトでなければならない（SHALL）。

| キー | 内容 | 型 |
|---|---|---|
| `id` | レシピの ID（ファイル名由来のスラッグ） | 文字列 |
| `title` | 料理名 | 文字列 |
| `title_yomi` | 料理名の読み | 文字列 |
| `ingredients` | 材料 | 文字列の配列（空要素は除く、前後の空白は除く） |
| `ingredients_yomi` | 材料の読み | 文字列の配列（`ingredients` と要素数・順序が対応する） |
| `auto_key` | 自動調理キー | 文字列（無ければ空文字） |
| `auto_key_yomi` | 自動調理キーの読み | 文字列（無ければ空文字） |
| `menu_no` | 自動メニュー番号 | 文字列（無ければ空文字。先頭ゼロを保つ） |
| `manual_note` | 手動設定 | 文字列（無ければ空文字） |
| `manual_note_yomi` | 手動設定の読み | 文字列（無ければ空文字） |
| `body` | 本文の検索用プレーンテキスト | 文字列（無ければ空文字） |
| `body_html` | 本文の表示用 HTML | 文字列（無ければ空文字） |

任意項目は「キーが無い」ではなく「空文字」で表し、下流が存在チェックをしなくてよいようにする。

読みはひらがなで表す。読みは検索で表記の違いを越えるために持つものであり、次の性質を持つ。

- 読みのキーは常に存在し、常に文字列である。元の表記がすでにひらがなで読みと同じ値になる場合も省略しない
- 読みを取得できなかった語は、その語だけ元の表記のまま残す（フィールド全体を空にはしない）
- 自動メニュー番号と本文には読みを持たない。自動メニュー番号は数字であり、本文は長文で読みを持つ利得が小さいため

#### Scenario: 全項目が埋まったレシピ
- **WHEN** frontmatter に全項目が書かれ、本文もあるレシピをビルドする
- **THEN** 出力オブジェクトは上記12キーをすべて持ち、各値が対応する内容になる

#### Scenario: 任意項目が無いレシピ
- **WHEN** `auto_key`・`menu_no`・`manual_note` を書いていないレシピをビルドする
- **THEN** 出力オブジェクトの該当キーは空文字になり、キー自体は存在する。対応する読みのキーも空文字になる

#### Scenario: 番号の先頭ゼロ
- **WHEN** frontmatter で `menu_no: "048"` と書く
- **THEN** 出力の `menu_no` は `"048"` のまま（数値 48 にならない）

#### Scenario: 材料の空白と空要素
- **WHEN** `ingredients` の要素に前後の空白や空文字の要素が混ざっている
- **THEN** 出力の `ingredients` は前後空白が除かれ、空要素は取り除かれる

#### Scenario: 漢字を含む料理名の読み
- **WHEN** 料理名が `サバの味噌煮` のレシピをビルドする
- **THEN** `title_yomi` は `さばのみそに` になる

#### Scenario: 材料の読みは元の材料と対応する
- **WHEN** 材料が3件あるレシピをビルドする
- **THEN** `ingredients_yomi` は要素数3の配列になり、各要素は同じ位置の材料の読みになる

#### Scenario: 読みが元の表記と同じになる場合
- **WHEN** 料理名がすべてひらがなで書かれたレシピをビルドする
- **THEN** `title_yomi` は空文字にならず、料理名と同じ値が入る

#### Scenario: 読みを取得できなかった語がある
- **WHEN** 読みを取得できない語を含む料理名のレシピをビルドする
- **THEN** `title_yomi` はその語だけ元の表記のまま残り、読みを取得できた語はかなになる

#### Scenario: 本文と自動メニュー番号には読みが無い
- **WHEN** 本文と自動メニュー番号があるレシピをビルドする
- **THEN** 出力オブジェクトに本文の読み・自動メニュー番号の読みにあたるキーは存在しない

### Requirement: ID は安定している
`id` はファイル名から一意に決まり、料理名や本文を変えても変わってはならない（SHALL NOT）。同じレシピは何度ビルドしても同じ `id` を持つ。

#### Scenario: 料理名を変更する
- **WHEN** 既存レシピの `title` だけを変更して再ビルドする
- **THEN** そのレシピの `id` は変わらない

#### Scenario: ファイル名を変更する
- **WHEN** レシピのファイル名を変更して再ビルドする
- **THEN** そのレシピの `id` は新しいファイル名に変わる（ID の付け替えは著者の意図的な操作）

### Requirement: 料理名順に並ぶ
配列は `title` の日本語ロケールでの昇順に並んでいなければならない（SHALL）。ビルドのたびに同じ入力からは同じ順序が得られる。

#### Scenario: 並び順
- **WHEN** 料理名「豚バラ大根」「サバの味噌煮」「蒸し野菜サラダ」のレシピをビルドする
- **THEN** 出力配列は日本語ロケールの照合順に並ぶ

#### Scenario: 再現性
- **WHEN** 同じレシピ群を2回ビルドする
- **THEN** 出力 JSON の内容と順序は同一になる

### Requirement: 本文はプレーンと HTML の2表現を持つ
`body` は本文の Markdown ソースを検索用にそのまま（前後の空白を除いて）保持し、`body_html` は本文を CommonMark に準拠して HTML に変換したものでなければならない（SHALL）。HTML 変換では、本文中に書かれた生の HTML タグを実行可能なタグとして通してはならず、エスケープされた文字として出力しなければならない（SHALL NOT / SHALL）。

#### Scenario: 見出しと箇条書きの変換
- **WHEN** 本文に `## 手順` と番号付きリストがある
- **THEN** `body_html` には見出し要素と順序付きリスト要素が含まれ、`body` には Markdown のまま含まれる

#### Scenario: 生の HTML を書いた場合
- **WHEN** 本文に `<script>` のような生の HTML タグを書く
- **THEN** `body_html` ではそれがタグとして解釈されず、エスケープされた文字（`&lt;script&gt;`）として出力される

#### Scenario: 本文が空
- **WHEN** 本文の無いレシピをビルドする
- **THEN** `body` と `body_html` はともに空文字になる

### Requirement: 生成物のコミット方針
検索インデックスはビルド生成物であり、リポジトリにコミットしてはならない（SHALL NOT。バージョン管理から除外する）。手元・CI のいずれでも、ビルドを実行すれば同じ入力から再生成できる。

#### Scenario: クリーンな作業ツリーでビルドする
- **WHEN** リポジトリを取得した直後にビルドを実行する
- **THEN** 検索インデックスが生成され、作業ツリーに未追跡の変更として現れない（無視対象になっている）
