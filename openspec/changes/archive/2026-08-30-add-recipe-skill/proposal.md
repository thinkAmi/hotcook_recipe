# add-recipe-skill

## Why

レシピは「一度作って、これで行けると感じたもの」を調理直後の振り返りとして記録する。しかし記録の頻度が低いからこそ、frontmatter の形式（`menu_no` の引用符、`ingredients` のリスト形式、ローマ字スラッグの命名など）を毎回思い出して手書きするのは負担であり、fail fast のビルドで初めて誤りに気づくことになる。聞き書きでレシピファイルを生成し、その場でビルド検証まで済ませる仕組みがほしい。

あわせて、探索の中で「材料はホットクックに投入する順で書いている」という暗黙の規約が見つかった。分量が分かっても投入順が分からないと調理時に迷うため、この規約は生成の仕組みの中だけでなく、レシピ形式の要件として明文化する。

## What Changes

- レシピの聞き書き・生成の仕組みを新設する。著者の語りから対話で聞き取り、レシピ形式に準拠した Markdown ファイルを生成し、ビルド検証（fail fast・読みの警告確認）まで行う
- 材料の並びを勝手に並べ替えない（区分順への整列など、生成側の「善意の改変」を禁じる）。順序が不明確な場合は投入順を確認してから整形する
- ローマ字スラッグは候補を提示し、著者が承認する（「ファイル名は著者が付ける」という既存要件を保つ）
- `recipe-authoring` に「材料は投入順で並べ、ビルドはその順序を保持する」という要件を追加する

## Non-goals（やらないこと）

- コミットの自動化はしない。生成とビルド検証で止め、コミットは著者が確認してから既存の流れで行う
- 自動メニュー番号と自動調理キーの対応表は持たない。番号は記録のたびに著者が都度書く（かき混ぜユニットを使わない番号に絞られており、都度入力で足りる）
- Claude Code の外（スマホ等）で使うポータブルなプロンプト文書は今回は作らない
- 読みの推測はしない。ビルドの警告は提示し、著者が読みを口にした場合の書き取りは行うが、スキルが読みを推測して勝手に埋めることはしない
- 既存レシピの一括変換ツールは作らない

## Capabilities

### New Capabilities

- `recipe-capture`: 著者の語りからレシピファイルを聞き書きで生成する振る舞い。必須項目の聞き取り、投入順の保持、スラッグの承認、生成後のビルド検証までを扱う

### Modified Capabilities

- `recipe-authoring`: 材料の並びに「投入順」という意味を与える要件を追加する。ビルドは材料の順序を保持しなければならない

## Impact

- 生成の仕組み（スキル）をリポジトリに追加する
- `recipe-authoring` の spec に要件が1つ増える。ビルドスクリプトはもともとリスト順を保持しているため、実装変更は順序保持を検証するテストの追加が中心になる見込み
- 既存レシピ3件の材料が投入順になっているかの点検が必要（なっていなければ並べ替える）
