# recipe-capture 仕様

## ADDED Requirements

### Requirement: 語りから聞き取り、不足だけを確認する
聞き書きは、著者の自由な語りから料理名・材料・調理方法（自動調理キー・自動メニュー番号・手動設定）・手順・メモを読み取らなければならない（SHALL）。すでに語られた項目を訊き直してはならない（SHALL NOT）。不足している項目のうち、必須のもの（料理名・材料）は確認し、任意の調理方法は一度だけまとめて確認する。手順・メモが語られなければ本文は空でよい。

#### Scenario: 一括で語られた場合は質問しない
- **WHEN** 著者が料理名・材料・調理方法を一度に語る
- **THEN** 聞き書きは追加の質問をせず、生成前の確認へ進む

#### Scenario: 料理名が語られていない
- **WHEN** 語りに料理名が含まれていない
- **THEN** 聞き書きは料理名だけを確認する

#### Scenario: 調理方法はまとめて一度だけ確認する
- **WHEN** 語りに自動調理キー・自動メニュー番号・手動設定のいずれも含まれていない
- **THEN** 聞き書きは調理方法を一度だけまとめて確認し、「無し」と答えられたらどの項目も書かずに進む

### Requirement: 材料は語られた順を投入順として保持する
聞き書きは、語られた順を投入順として採用しなければならない（SHALL）。区分順への整列その他、順序の変更を行ってはならない（SHALL NOT）。語り方から順序が投入順と読めない場合（材料が区分でまとめて語られた場合など）は、整形の前に投入順を確認しなければならない（SHALL）。

#### Scenario: 順に語られた材料はそのままの順で記録される
- **WHEN** 著者が「大根、豚バラ 200g、めんつゆの順で入れた」と語る
- **THEN** 生成されるレシピの材料はその順のまま並ぶ

#### Scenario: 区分でまとめて語られたら投入順を確認する
- **WHEN** 著者が「材料は豚バラと大根、味付けはめんつゆ」のように区分で語る
- **THEN** 聞き書きは投入順を確認してから材料を整形する

#### Scenario: 材料は1行の形式に整えられる
- **WHEN** 著者が「サバを2切れ」のように語る
- **THEN** 生成される材料は「サバ 2切れ」のような量・単位を分けない1行に整えられる

### Requirement: 語られていない内容を補わない
聞き書きは、著者が語った内容だけを記録しなければならない（SHALL）。語られていない材料・分量・手順を推測で補ってはならない（SHALL NOT）。

#### Scenario: 分量が語られなかった材料
- **WHEN** 著者が分量を添えずに「しょうが」とだけ語る
- **THEN** 生成される材料は「しょうが」のままで、分量が創作されることはない

#### Scenario: 一般的な手順を足さない
- **WHEN** 著者が手順を語らない
- **THEN** 本文は空になり、一般的な調理手順が補われることはない

### Requirement: レシピの ID は候補を提示し著者が承認する
聞き書きは、レシピの ID（ローマ字のスラッグ）の候補を既存レシピの流儀に沿って提示し、著者の承認を得てからレシピを作らなければならない（SHALL）。既存レシピと同じ ID になる場合は、承認の前にそのことを伝え、別の候補を示さなければならない（SHALL）。

#### Scenario: 候補を承認する
- **WHEN** 聞き書きが提示した ID の候補を著者が承認する
- **THEN** その ID でレシピが作られる

#### Scenario: 候補を修正する
- **WHEN** 著者が候補とは別の ID を指定する
- **THEN** 著者が指定した ID でレシピが作られる

#### Scenario: 既存レシピと ID が衝突する
- **WHEN** 候補の ID を持つレシピがすでに存在する
- **THEN** 聞き書きはそのことを伝え、別の候補を提示する（既存レシピを上書きしない）

### Requirement: 生成前に全文の承認を得る
聞き書きは、レシピを作る前に、ID とレシピの全文を一度にまとめて提示し、著者の承認を得なければならない（SHALL）。承認前に修正の指示があれば、反映して再提示する。

#### Scenario: 全文を承認して生成する
- **WHEN** 提示された全文を著者が承認する
- **THEN** その内容でレシピが作られる

#### Scenario: 修正を指示する
- **WHEN** 著者が提示内容の修正（材料の順の入れ替えなど）を指示する
- **THEN** 聞き書きは修正を反映した全文を再提示し、承認を得てからレシピを作る

### Requirement: 生成後にビルドで検証する
聞き書きは、レシピを作った後にビルドを実行し、その結果を著者に報告しなければならない（SHALL）。ビルドが失敗した場合（必須項目の欠落・frontmatter の破損など）、それは生成した内容の不備なので、聞き書きが自ら修正して再度ビルドしなければならない（SHALL）。著者に修正作業を求めてはならない（SHALL NOT）。

#### Scenario: ビルドが成功する
- **WHEN** 生成したレシピでビルドが成功する
- **THEN** 聞き書きは作られたレシピとビルド結果を報告して終える

#### Scenario: ビルドが失敗する
- **WHEN** 生成したレシピの不備でビルドが失敗する
- **THEN** 聞き書きは生成した内容を自ら修正して再度ビルドし、修正の経緯とともに結果を報告する

#### Scenario: 先頭のゼロを持つ自動メニュー番号
- **WHEN** 著者が自動メニュー番号として「052」を伝える
- **THEN** 生成されたレシピは先頭のゼロを保った「052」を記録し、ビルドを通過する

### Requirement: 読みの警告は提示し、口述された訂正だけを書き取る
ビルドが読みの警告（読みを取得できなかった語、読みに漢字が残る項目）を報告した場合、聞き書きはそれを著者に提示しなければならない（SHALL）。著者がその語の読みを口にした場合は、対応表の著者が訂正する部分へ書き取らなければならない（SHALL）。著者が読みを示さない場合、聞き書きが読みを推測して訂正を加えてはならない（SHALL NOT）。

#### Scenario: 著者が読みを口にする
- **WHEN** 「蓮根」の読みが取れない警告に対し、著者が「れんこん」と読みを口にする
- **THEN** 聞き書きはその読みを対応表の訂正として書き取り、再ビルドで警告が消えたことを確認する

#### Scenario: 著者が読みを示さない
- **WHEN** 読みの警告に対して著者が読みを示さない
- **THEN** 聞き書きは訂正を加えず、警告が残っている旨を報告して終える

### Requirement: コミットは行わない
聞き書きは、生成したレシピや訂正をコミットしてはならない（SHALL NOT）。ビルド検証までで終え、コミットは著者が内容を確認してから行う。

#### Scenario: ビルド成功後もコミットしない
- **WHEN** 生成とビルド検証が成功して聞き書きが終わる
- **THEN** 変更はコミットされない状態で残り、報告にはその旨が含まれる
