- [ ] 2.3 取得部分で、空白を含む文字列をそのまま渡さず、空白で区切ってから語ごとに渡す。中国語と誤判定される（実測: `生姜 1片` → 「しぇえんぐじああんぐ…」）（D-14 帰結）

## 3. 対応表の生成

- [ ] 3.1 レシピの料理名・材料・自動調理キー・手動設定から語を抜き出し、`data/yomi.generated.json` をまるごと書き直す生成処理を作る（要件: 語と読みの対応表を保持する／要件: 再生成は著者の訂正を変更しない）
- [ ] 3.2 読みを取得できなかった語は `null` として残す（要件: 読みを取得できなかった語が分かる）
- [ ] 3.3 生成は `data/yomi.overrides.json` を読み書きしない。訂正が失われないことをファイル境界で保証する（要件: 再生成は著者の訂正を変更しない／D-15）
- [ ] 3.4 取得に失敗した場合は生成全体を中止し、既存の対応表を1バイトも書き換えない（要件: 生成に失敗したときは対応表を変更しない）
- [ ] 3.5 生成処理の単体テストを書く。実測で判明している誤読（`葱→き`、`米→べい`）と正しい読み（`大蒜→にんにく`、`味醂→みりん`）を例として固定する（D-14 帰結・D-27）
- [ ] 3.6 プロパティベーステストを書く。**検証する性質: 再生成の非破壊性**——任意の訂正の集合に対し、自動生成部分をどのように作り直しても訂正の内容は変化しない（D-27 (c)）
- [ ] 3.7 実際に対応表を生成し、生成された読みを目で確認してからコミットする。誤読があれば `data/yomi.overrides.json` に訂正を書く（D-15・D-16）

## 4. ビルドへの読みの組み込み

- [ ] 4.1 対応表を読み込み、自動生成部分に訂正を重ねてマージする処理を純関数として作る（要件: 語と読みの対応表を保持する）
- [ ] 4.2 マージ済みの表のキーを長い順に並べ、文字列の先頭から最長一致で読みに置換する処理を純関数として作る。分割器は持たない（D-17）
- [ ] 4.3 読みを取得できなかった語（`null`）は、その語だけ元の表記のまま残す（要件: レシピオブジェクトの形／D-18 帰結）
- [ ] 4.4 検索インデックスに `title_yomi`・`ingredients_yomi`・`auto_key_yomi`・`manual_note_yomi` を出力する。読みのキーは常に存在し常に文字列にする（要件: レシピオブジェクトの形／D-18）
- [ ] 4.5 `ingredients_yomi` が `ingredients` と要素数・順序で対応することを保証する（要件: レシピオブジェクトの形）
- [ ] 4.6 自動メニュー番号と本文には読みを持たせない（要件: レシピオブジェクトの形／D-18）
- [ ] 4.7 対応表が読み取れない、または自動生成部分が存在しない場合はビルドを失敗させ、検索インデックスを出力しない（要件: 対応表を読めないときはビルドを失敗させる）
- [ ] 4.8 訂正がまだ1件も無い場合はビルドを成功させる（要件: 語と読みの対応表を保持する）
- [ ] 4.9 3種の警告を出す。(1) 読みが `null` のまま訂正も無い語、(2) どのレシピにも現れなくなった語の訂正、(3) 自動生成された読みと同じ値になった訂正。いずれもビルドは失敗させない（要件: 読みを取得できなかった語が分かる／要件: 不要になった訂正を知らせる）
- [ ] 4.10 上記の単体テストとフィクスチャを追加する（正常系、`null` を含む表、訂正あり、壊れた表、表が無い）（D-27）
- [ ] 4.11 プロパティベーステストを書く。**検証する性質: マージ規則の不変条件**——訂正のある語では、自動生成側の値がどうであっても必ず訂正の値が採られる（D-27 (b)）

- [ ] 5.14 検索インデックスを取得できないとき、その旨を表示し、一致0件の表示と区別できるようにする（要件: レシピを読み込めないときは知らせる）
