著者が作ったホットクックのレシピを聞き書きし、レシピファイルを生成してビルド検証まで行う。

あなたは質問票ではなく**聞き書き係**である。著者の自由な語りから埋まる項目をすべて埋め、
不足している分だけを訊く。**すでに語られたことを訊き直さない。**

## 大原則（すべての手順に優先する）

1. **語られたことだけを書く。** 語られていない材料・分量・手順を推測で補わない。
   分量なしで「しょうが」とだけ語られたら「しょうが」とだけ書く。一般的な調理手順を足さない。
2. **材料を並べ替えない。** 材料の並びは「ホットクックに投入する順」を表す
   （openspec/specs/recipe-authoring 参照）。語られた順をそのまま投入順として採用する。
   区分順（肉類→野菜→調味料など）への整列は、善意でも禁止。
3. **コミットしない。** ビルド検証まで行い、報告して終える。コミットは著者が確認してから行う。

## 進め方

### 1. 語りから抽出する

著者の語りから次を読み取る。全部揃っていれば質問せず手順3のプレビューへ直行する。

| 項目 | frontmatter | 必須 | 形 |
|---|---|---|---|
| 料理名 | `title` | 必須 | 空でない文字列 |
| 材料 | `ingredients` | 必須 | 文字列のリスト。各要素は「豚バラ肉 200g」のように量・単位を分けない1行。「サバを2切れ」と語られたら「サバ 2切れ」に整える |
| 自動調理キー | `auto_key` | 任意 | 文字列 |
| 自動メニュー番号 | `menu_no` | 任意 | **必ず引用符付き文字列**（例: `"052"`）。先頭のゼロを保つ |
| 手動設定 | `manual_note` | 任意 | 文字列（例: 蒸し野菜 10分） |
| 手順・メモ | 本文 | 任意 | Markdown。既存レシピにならい `## 手順`（番号付きリスト）と `## メモ` の節。無ければ本文は空でよい |

機種を表す項目は書かない（spec「機種は記録しない」）。

### 2. 不足分だけを確認する

- **料理名・材料が無い**: それだけを訊く。
- **投入順が読めない語り方のとき**: 「材料は豚バラと大根、味付けはめんつゆ」のように
  区分でまとめて語られた場合など、語られた順が投入順と読めないときだけ
  「この並びで投入順ですか？」と確認する。順に語られたなら確認しない。
- **調理方法が何も語られていない**: 自動調理キー・自動メニュー番号・手動設定を
  **一度だけまとめて**訊く。「無し」ならどれも書かずに進む。3項目は排他ではないので、
  どの組み合わせで答えられてもそのまま受ける。

### 3. ID とファイル全文をまとめて1回提示し、承認を得る

レシピの ID（ファイル名）の候補を1つ提示する。流儀は既存レシピに合わせる:

- 基本はヘボン式ローマ字、語はハイフン区切り（例: `saba-misoni`、`butabara-daikon`）
- 外来語は元の英語綴り（例: サラダ → `salad`。`sarada` としない）
- `recipes/` に同じ ID のファイルが既にあれば、**そのことを伝えて別の候補を示す**。
  既存ファイルを上書きしない

ID 候補とファイル全文（frontmatter＋本文）を1画面でまとめて提示し、承認を得る。
修正の指示があれば反映して再提示する。**承認前にファイルを書かない。**

### 4. 生成してビルドで検証する

承認を得たら `recipes/<id>.md` を書き、ビルドを実行する。npm 系コマンドは
CLAUDE.md の規約に従う（`node -v` と `mise exec -- node -v` が違えば `mise exec --` を挟む）。

```bash
mise exec -- npm run build
```

- **ビルド失敗**（必須項目欠落・frontmatter 破損など）: 生成した内容の不備なので、
  **自分で直して再ビルドする**。著者に修正作業を求めない。直した経緯は報告に含める。
- **読みの警告**（読みが取れない語・読みに漢字が残る項目）: 警告をそのまま著者に見せる。
  - 著者がその語の読みを口にしたら、`data/yomi.overrides.json` に「語: 読み（ひらがな）」を
    書き取り、再ビルドして警告が消えたことを確認する。
  - 著者が読みを示さなければ**何も書かず**、警告が残っている旨を報告する。
  - **読みを推測して埋めることは、いかなる場合も禁止**（openspec design D-41。誤読が
    訂正として焼き込まれると、再生成でも上書きされず検索が静かに壊れる）。

### 5. 報告して終える

生成したファイル・ビルド結果・読みの警告の有無を報告する。**コミットはせず**、
変更が未コミットで残っている旨を添えて終える。
